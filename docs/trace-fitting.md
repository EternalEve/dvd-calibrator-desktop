# 人工描线拟合与导出（0.5.0）

## 操作

```powershell
dotnet run --project src/DvdCalibrator.App -c Release -- --trace-demo
```

演示照片由完整正向模型生成，带已知双圆和两条径向线。点击“拟合描线”，核对橙色预测线，
再“确认候选曲线”“导出补偿配置”。它是软件测试图，不是相机或实盘效果证明。

真实任务必须使用这张盘实际生成时的冻结快照。粗调照片读取 G0；第二张精调照片必须读取它自己的 G1，
不能沿用第一张的生成条件。同一个描线入口处理这两类可追踪边界；0.5.0 增加独立计划和两盘关联，见 [两盘工作流](two-disc-workflow.md)。
固定参考靶的主线应取明确的右侧十字中心线，对侧线相差 180°；不把近旁圆环边缘或十字外轮廓混作中心线。

确认双圆矫正后，在“主径向线描点”中从内到外沿**同一条源径向边界**取 24–600 点，建议 40 点以上，
覆盖生成环带径向宽度至少 60%。不自动排序、删点或跳到另一条臂。
主线末段 25% 不参与优化和转角估计；其角度、残差与切线权重不进入训练。
候选仍须覆盖所有观测半径，不能通过丢掉边界点绕过有效域检查。

若原图案确实有对侧径向线，可在“对侧 180° 留出线”模式描它（6–600 点，同样覆盖 60%）。
它全部用于检查，源角差固定为 pi；不得将任意另一条臂当成对侧线。每条完整线只允许一个统一整圈偏移。
该入口不适用于任意弯曲源图边界、密集环、漏圈后不可连续追踪的条纹。

## 拟合模型和验证

- 固定真实扇区数、生成位长和方向，拟合半径及可选形状；保留原快照的非零系数。
- 完整共享几何计算 `theta_A(r) - theta_G(inverse_u_G(u_A(r)))`，照片整体转角为独立拟合量。
- 从源像素重投影到毫米坐标后连续展开角度，不为各点单独添加整圈来贴合模型。
- 默认“保留轨距形状”，只修半径。搜索从 ±0.02 mm 开始，必要时扩大到 ±0.1 / ±0.5 mm。
- 选一至三阶形状至少需 40 个主线点。形状范围相对原系数默认 ±0.05；未改善连续留出区至少 20%，或低阶留出误差已小于 0.005 mm 时，高阶不获确认资格。
- 采用有界多起点 LM 与 Huber 误差；法向距离尺度来自观测切线，不来自候选自己的斜率。
- 同时报告训练 RMS、留出 RMS、全部点的最大偏差、边界命中及参数列相关性。降权点仍留在报告中。

当前工程门槛为训练/留出 RMS <=0.35 mm、最大偏差 <=0.8 mm，默认稳健尺度 0.1 mm。
这些是筛查门槛，不是经真实照片集校准的成功率或物理精度声明。
相邻观测角差 >=pi/2 会要求补点；预测在观测间的 sampled 相位变化过大或采样不足，也会阻止确认。
此采样检查不是严格的全局曲线误差定理，不能证明点间不存在漏圈。

橙色为完整参数模型预测，黄色为训练点，绿色为留出点，红色为偏离较大的点。
选择候选后检查全部可见曲线，尤其点间和未参与拟合的区域。人工确认不能替代不够的信息，
边界命中、误差超限、高阶无证据或有明显预测冲突的候选不能确认导出。

状态 `fit-review` 表示可以核对候选，并不等同于最终向导的 `coarse-ready`、`fine-ready` 或实刻通过。
有限多起点并非穷尽；参数相关提示与拟合误差分开，结果称为固定位长条件下的等效补偿。

## 保存与导出

任务包新增可选 `fit.json`，绑定快照、完整照片会话哈希、求解设置、候选、残差、连续曲线和确认。
修改照片观测、遮罩、描点或矫正会使旧拟合失效；改变形状设置或候选选择清除对应确认。
0.2.0 读取器不认识新增 fit 条目，新版仍支持无 fit 条目的旧任务。

导出新目录包含：

| 文件 | 内容 |
| --- | --- |
| `calibration-profile.json` | 完整双精度半径、容量、位长、系数、方向、起点及输入/确认关联 |
| `fit-review.json` / `photo-session.json` | 完整求解诊断与原始像素观测记录 |
| `residuals.csv` / `curve.svg` | 全点残差、训练/留出身份、连续预测线与输入点 |
| `report.html` | 参数、误差、曲线、兼容应用说明与限制 |
| `candidate.discproj` | 仅在目标格式可表达全部必要几何条件时生成的空图层工程 |

目标基准是固定上游提交 `374c0630326ea61be9adca8d7de3c96f083c00df`。
其 `.discproj` 不保存独立 DVD 位长与方向，因此仅在 133.3 nm、CW、零起点和 16 扇区对齐时输出工程。
使用上游原始 `ProjectJsonStore.Save/Load` 回读并比较全部几何字段。
工程没有预置图层，需要导入正式图片；输出路径是本次导出位置，移动工程后应重新指定输出位置。
不兼容时保留完整主配置和说明，不能把位长/方向改回默认值来强行导出工程。
照片转角只用于曲线对照，不写入生成角度。工程回读不等于 GUI 已应用，更不等于实刻通过。

所有结果 `physicalValidation=pending`。当前没有全链路轮廓不确定度传播、跨实盘批次重复性或真实介质盲测。

## 命令行

```powershell
dotnet run --project src/DvdCalibrator.Cli -c Release -- fit-trace --generated fixtures/trace-fit-generation.synthetic.json --session fixtures/trace-fit-session.synthetic.json --out artifacts/fit-001
dotnet run --project src/DvdCalibrator.Cli -c Release -- export-profile --review artifacts/fit-001/fit-review.json --session artifacts/fit-001/photo-session.json --confirm-curve true --out artifacts/profile-001
```

`fit-trace` 可加 `--shape-order 1/2/3`。输出目录必须不存在。
`export-profile` 要求显式 `--confirm-curve true`，表示调用者已核对照片和完整曲线；程序不会自动勾选此声明。
这些 CLI 入口处理 JSON 几何/观测，照片附件验证仍由完整任务包流程执行。
